# Правки raducan.pro — удаление /tools + чистка кодировки

24 мая 2026

## Контекст

Две задачи в одном заходе:

1. **Удалить раздел `/tools` целиком** (три калькулятора: окупаемость кальянной, регулярные инвестиции, чек-лист системы учёта клиентов). Раздел перетягивает фокус, не укладывается в текущее позиционирование («оптимизация бизнеса в HoReCa и e-com»). Потеря SEO-трафика от запроса «калькулятор окупаемости кальянной» принята осознанно.
2. **Починить кодировку**: на проде видны битые символы `��` и одиночные `?` между кириллическими буквами в нескольких местах (на скриншоте /tools — «инструменты **��**ля бизнеса», «Ра**��**ходы», «ме**��**яц»; есть подобные следы и в других местах). Это нужно вычистить **по всему проекту**, а не только на удаляемой странице.

## Список правок

### 1. Удалить директорию tools
- **Где:** `src/app/[locale]/tools/`
- **Как:** удалить директорию целиком (`page.tsx`, `layout.tsx` и любые вложенные файлы).

### 2. Убрать `/tools` из Navbar
- **Где:** `src/components/Navbar.tsx`
- **Как:** удалить элемент `{ href: "/tools", label: t("tools") }` из массива `navLinks`. После правки в массиве должны остаться: about, blog, contact.

### 3. Убрать `/tools` из Footer
- **Где:** `src/components/Footer.tsx`
- **Как:** удалить `<Link href="/tools">` в колонке Company (где сейчас перечислены about, blog, tools).

### 4. Удалить i18n ключи `tools`
- **Где:** `messages/ru.json` и `messages/en.json`
- **Как:** удалить:
  - `nav.tools`
  - `footer.tools`
  - `metadata.tools` (весь блок с title/description)
  - Если в файле есть отдельный раздел `tools.*` (контент калькуляторов) — удалить целиком.

### 5. Sitemap
- **Где:** `src/app/sitemap.ts`
- **Как:** убрать запись `/tools` если она там явно перечислена. Если sitemap генерируется автоматически по файловой системе — после удаления директории `/tools` он сам перестанет её включать, проверить.

### 6. SEO-утилита
- **Где:** `src/lib/seo.ts`
- **Как:** удалить запись для ключа `tools`, если есть в карте `buildPageMetadata`.

### 7. Routing-конфиг
- **Где:** `src/i18n/routing.ts`
- **Как:** если в `pathnames` явно перечислен `/tools` — удалить.

### 8. Чистка кодировки по всему проекту
- **Где:** весь проект, кроме `node_modules`, `.next`, `dist`
- **Как:** прогнать четыре варианта grep:
  ```
  rg -n "��" src/ messages/
  rg -nP "\?\?" src/ messages/
  rg -nP "(?<=[а-яА-ЯёЁ])\?(?=[а-яА-ЯёЁ])" src/ messages/
  rg -nP "(?<=[а-яА-ЯёЁ])\?(?=\s)" src/ messages/
  ```
  Первый ловит `��` (классический mojibake). Второй — `??` (двойные знаки вопроса как замена байтов UTF-8). Третий и четвёртый — одиночный `?` между кириллицей или после кириллицы перед пробелом (где должна была быть буква, а её декодер не распознал).

- Для каждого найденного места: определи по контексту правильную букву и замени. Известные точки на /tools (которая уже будет удалена пунктом 1, но проверь — могут быть аналогичные следы в `messages/*.json`, `*.mdx` блога, инлайн-строках компонентов):
  - `��ля` → `для`
  - `Ра��ходы` → `Расходы`
  - `ме��яц` → `месяц`

- После починки — прогнать все четыре grep'а повторно. Все должны быть пустыми (или показывать только корректные `?` в концах предложений, не между буквами).

- **Важно по кодировке файлов:** убедись, что все файлы сохраняются в **UTF-8 без BOM**. Если какой-то `.mdx` или `.json` лежит в Windows-1251 или с BOM — могла быть причина порчи. Перекодируй явно. В VS Code: правый нижний угол → `Reopen with encoding` → проверить → `Save with encoding: UTF-8`.

### 9. Финальный grep на остатки `/tools`
```
rg -n "/tools" src/ messages/
```
Должна быть пустота. Допустимы только совпадения в Telegram-хэндле (если есть) или в комментариях кода (не клиентский текст).

### 10. Build, deploy, push
- `npm run build` — зелёный.
- `npm run lint` — не больше существующих pre-existing предупреждений.
- `git add -A && git commit -m "feat: remove /tools section + repair UTF-8 mojibake across project"`
- `git push origin main`
- `python redeploy.py`
- Проверка после деплоя:
  - `curl -I https://raducan.pro/ru/tools` → **404**
  - `curl -I https://raducan.pro/ru` → **200**
  - Глазами на проде: в шапке нет пункта «Инструменты», в подвале нет ссылки на инструменты.

## Правила работы

- Следуй `CLAUDE.md` / `AGENTS.md`.
- Минимум, ничего лишнего.
- **EN-локаль также чисти от ключей `tools`** (это уже не «не трогаем» как в Phase 2 — раздел удаляется целиком в обеих локалях).
- Кодировка файлов — строго UTF-8 без BOM.
- Деплой и пуш — сам, по обычной схеме.
- В финале пришли отчёт: список изменённых/удалённых файлов, результаты четырёх grep'ов из пункта 8 после правки, результат grep `/tools` из пункта 9, HTTP-статус /tools (должен быть 404).
