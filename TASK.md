# Правки raducan.pro — этап 2: русификация под 168-ФЗ

24 мая 2026

## Контекст

С 1 марта 2026 действует **ФЗ-168** (расширение ФЗ-53 «О государственном языке» и ФЗ-38 «О рекламе»). Публичные тексты на сайтах, в рекламе, на вывесках, в меню — должны быть на русском. Иностранные бренды без зарегистрированного товарного знака и иностранные термины без русского эквивалента **запрещены**. Штрафы для ИП/юрлиц: **100 000 – 500 000 ₽**. Контролируют Роспотребнадзор и ФАС.

**Цель этапа:** русифицировать в RU-локали сайта raducan.pro:

- бренд `Raducan` → `РАДУКАН` (логотип) / `Радукан` (склонение в теле текста)
- термины `CRM`, `SaaS`, `MVP`, `HoReCa`, `ROI`, `DCA` — заменить на русские эквиваленты или дать русское пояснение

Этап 1 (чистка фейк-портфолио) уже задеплоен — состояние сайта чистое, проверь `git log --oneline -5`.

- **Технические термины в коде:** Next.js, TypeScript, Tailwind, React, npm, git, имена классов, переменных, файлов, npm-пакетов — это исходный код, не публичный текст. Не трогать.

### 2. Логотип в Footer

### 3. Тексты компонентов в ru.json — бренд
- **Где:** `messages/ru.json`
- **Как:** все встречающиеся в значениях ключей слова `Raducan` (как название компании) заменить на `РАДУКАН` (для заголовков/eyebrow/CAPS) или `Радукан` (в склоняемом тексте). Контекст подскажет вариант. EN-локаль не трогать.

### 4. Metadata — titles в ru.json
- **Где:** `messages/ru.json` → раздел `metadata.*.title`
- **Как:**
  - `Raducan` → `РАДУКАН`
  - Заголовки очистить от английских аббревиатур по таблице замен. Пример: `metadata.home.title: "Raducan — CRM, SaaS и автоматизация для малого бизнеса"` → `"РАДУКАН — учёт клиентов, онлайн-сервисы и автоматизация для малого бизнеса"`.

### 6. Hero — тексты в ru.json

### 16. Блог — body статей
- **Где:** `src/content/blog/*.mdx` — все файлы
- **Как:** применить правила таблицы замен в теле текстов. Особое внимание:
  - **Заголовки H1–H3 внутри статей** → русский эквивалент без аббревиатуры. Если статья сама про термин (например `chto-takoe-saas.mdx`) — допустимо использовать аббревиатуру в заголовке с русским пояснением рядом.
  - **Первое упоминание термина в статье** → «русское пояснение (аббревиатура)».
  - **Дальнейшие упоминания** → можно «аббревиатура-система» или просто аббревиатура.
  - **Бренд** в теле — `Raducan` → `Радукан` (склонение по контексту).

Поскольку статей 60+, делай поэтапно. После каждых ~10 файлов — `git diff --stat` и пауза, чтобы можно было быстро проверить промежуточный результат.

### 17. /tools — калькуляторы
- **Где:** `src/app/[locale]/tools/page.tsx` (RU-локаль) и связанные тексты в коде
- **Как:**

  - `Калькулятор DCA-инвестиций` → `Калькулятор регулярных инвестиций`
  - Лейблы полей и подписи внутри калькуляторов — проверить и заменить английские термины. `ROI` в результате расчёта оставить (это математическая аббревиатура, рядом с числом — нормально), но в заголовке и описании — русское.

### 18. Шрифты — проверить кириллический subset
- **Где:** `src/app/layout.tsx` (или где `import { ... } from "next/font/..."`)
- **Как:** убедиться, что Inter (и любой другой используемый шрифт) загружается с `subsets: ['cyrillic']` или `['cyrillic', 'latin']`. Без этого кириллические буквы будут падать на системный fallback и выглядеть неконсистентно. Если subset не задан — добавить.

### 19. Финальный grep
- **Как:** прогнать в корне проекта:
  ```
  rg -n "Raducan" src/ messages/ru.json src/content/blog/
  rg -nE "\b(CRM|SaaS|MVP|HoReCa|ROI|DCA)\b" messages/ru.json
  rg -nE "\bSale\b" src/ messages/
  ```
- **Жду:** в первом — пустоту или только нейтральные комментарии (например в комментариях кода — не клиентский текст). Во втором — пустоту или только в `services.crmTitle`/`saasTitle` если решено их оставить. В третьем — пустоту.
- Для блога допустимо, что в `*.mdx` аббревиатуры остаются — но в каждой статье должно быть русское пояснение при первом упоминании. Если по какой-то конкретной статье есть сомнения — спроси.

### 20. Build, lint, deploy, push
- `npm run build` — зелёный.
- `npm run lint` — не больше существующих 1 ошибки + 6 предупреждений (которые были в Phase 1).
- `git add -A && git commit -m "feat(i18n): rusification under 168-FZ — brand, terms, blog"` (или похожее)
- `git push origin main`
- Запустить деплой: `python redeploy.py` (как в Phase 1).
- Проверить: `curl -I https://raducan.pro/ru` → 200, `curl -I https://raducan.pro/en` → 200.
